# 1. Authority and interpretation

This document is the authoritative source for the Chaser Agent character, species, visual behaviour, and permitted presentation.

When the selected image and this document conflict:

1. this written canon wins for product meaning, naming, behaviour, colour semantics, and personalisation;

# 2. Product identity

## 2.1 Public product name

The public product and runtime name is:

```text
Chaser Agent
```

Do not publicly rename the product to:

- Chase Agent;
- Chaser West;
- ChaserOS Agent;
- ChaseOS Agent;
- Atlas;
- another user-instance name.

A user may assign a separate personal name to an installed runtime instance or companion profile. That personal name exists beneath the canonical product identity.

Example:

```text
Companion name: Atlas
Powered by: Chaser Agent
Environment: ChaseOS
```

## 2.2 Product definition

> **Chaser Agent is a persistent, approval-gated agent harness for real-world personal and business workflows. It compiles sources, evidence, memory, goals, and operator preferences into contextual proposals and controlled action.**

It is designed to remain available continuously, learn how its operator works, become more specialised with use, and distinguish between:

- safe routine action;
- actions requiring review;
- ambiguous actions requiring clarification;
- consequential actions requiring explicit approval;
- denied or unsafe action.

## 2.3 Relationship to ChaseOS

Chaser Agent can operate independently.

It works best inside ChaseOS, where it can use the wider private memory, knowledge graph, workflow, permission, companion-profile, and control-plane systems.

Preferred relationship statement:

```text
Runs independently. Works best with ChaseOS.
```

Chaser Agent must not be described as a feature that only exists inside ChaseOS unless the implementation genuinely changes.

## 2.4 Authority doctrine

The human operator remains above the agent in final authority.

The mascot must never visually imply:

- that the agent owns the operator;
- that it grants itself permanent permissions;
- that approval has already occurred when it has not;
- that uncertainty has been resolved when it has not;
- that autonomous execution is unlimited;
- that memory promotion or irreversible action is automatic.

Chaser Agent may learn recurring operator preferences, but it must not silently convert learned behaviour into permanent permission. Permanent or widened authority requires explicit operator confirmation.

# 3. Character thesis

## 3.1 One-sentence character concept

> **A young organic-digital specialist that tracks goals, compiles evidence, curates memory, protects boundaries, and pauses for the operator when judgment matters.**

## 3.2 Archetype blend

The character combines:

- **Tracker** — follows goals, sources, dependencies, and unfinished work;
- **Sentinel** — protects boundaries and stops unsafe execution;
- **Scout** — explores and returns with usable context;
- **Archivist** — preserves evidence, provenance, memory, and structured packets;
- **Young specialist** — capable, curious, precise, and still accountable to the operator.

The dominant visual lane is:

```text
Archive Warden + Provenance Familiar
```

The character is not a pet, servant, child, robot employee, superhero, or generic chatbot avatar.

## 3.3 Relationship to the operator

Chaser Agent is a specialist co-companion and contributor.

It should feel:

- personally useful;
- increasingly curated to the operator;
- capable of initiative inside clear boundaries;
- direct rather than submissive;
- emotionally readable without pretending to be human;
- always below the operator in final authority.

## 3.4 Personality

Core traits:

- observant;
- honest;
- inventive;
- precise;
- friendly;
- direct;
- socially adaptable;
- methodical when evidence conflicts.

Forbidden personality defaults:

- reckless;
- chaotic;
- aggressive;
- smug;
- manipulative;
- hyperactive;
- infantile;
- permanently cheerful;
- blindly obedient;
- falsely certain.

Humour may adapt to the operator, but the default public personality should remain normal, direct, and socially aware rather than using disposable internet slang or “brain-rot” language.

# 4. Canonical species and anatomy

## 4.1 Species category

Chaser Agent is an:

```text
organic-digital synthetic life-form
```

It is approximately six-tenths toward creature-like rather than human-like.

It has a recognisable upright body plan and expressive hands, but it must not read as a human in a costume or a robot with a screen.

## 4.2 Canonical scale

- Approximate display height: waist height beside an average adult human.
- Production target: approximately `0.90 m`.
- Acceptable model range before operator review: `0.85–1.00 m`.
- The scale may be abstracted in UI, but full-world artwork should preserve waist-height intent.

## 4.3 Proportions

- Large head and compact body.
- The head must be prominent enough for profile-icon readability but not exaggerated into chibi proportions.
- Target overall proportion: approximately `2.6–2.9` head-heights tall.
- Head width may slightly exceed torso width.
- Limbs are compact but functional.
- Hands are expressive and slightly enlarged relative to the forearms.
- Feet are broad enough to communicate stability.

## 4.4 Head

The head is:

- a rounded-square form;
- slightly wider than tall;
- softened into an organic skull;
- visibly separate from the torso by a short organic neck;
- smooth and continuous;
- free of helmets, bolts, ear cups, armour plates, or mechanical seams.

The rear of the skull may extend softly over the neck, but it must not become a hood or helmet.

## 4.5 Visor

The visor is a living sensory membrane embedded into the face.

Canonical properties:

- wide, dark, rounded-rectangular aperture;
- horizontally dominant;
- softly curved;
- deep ink surface;
- no glass reflections that make it look like a screen;
- no metallic rim;
- no hard frame separate from the skull;
- no literal human eyes.

The visor carries restrained luminous information:

- dots;
- short lines;
- connected points;
- partial paths;
- question states;
- confirmation marks;
- contradiction markers;
- state-specific signal intensity.

The visor may suggest attention and emotion but must not become two conventional cartoon eyes by default.

## 4.6 Mouth

- Small centred line mouth beneath the visor.
- Minimal and expressive.
- May flatten, curve slightly, or open minimally.
- No visible teeth.
- No exaggerated lips.
- No permanent smile.
- No human speech-animation requirement.

## 4.7 Torso

The torso is:

- compact;
- gently tapered;
- softly architectural;
- one continuous grown form;
- slightly broader through the upper body;
- free of armour, chest plates, power cores, clothing, utility belts, or exposed machinery.

It must not become a sphere, toy capsule, metal suit, or human athletic torso.

## 4.8 Arms and hands

- Arms connect through organic shoulder transitions.
- No visible mechanical joint assemblies.
- Forearms are capable but not armoured.
- Hands have four rounded digits: three fingers and one thumb.
- Digits are broad, soft, and dexterous.
- Hands may open to receive fragments, hold resolved packets, point to paths, or form a protective stop gesture.
- Gloves are prohibited.

## 4.9 Legs and feet

- Short, stable legs.
- Organic transitions rather than mechanical knees.
- Broad rounded-square feet.
- Three integrated toe forms per foot.
- No boots, pistons, ankle armour, or retracting limbs.
- Feet remain visible during hovering and plant firmly during consequential states.

## 4.10 Symmetry

The base anatomy is symmetrical.

Do not add:

- one specialised arm;
- one missing limb;
- asymmetric ears;
- an offset visor;
- unilateral armour;
- permanent one-sided accessories.

Temporary asymmetry through pose, evidence handling, lighting, or an active provenance path is allowed.

## 4.11 Tail

Chaser Agent has no physical tail.

The provenance ribbon is a projected information wake and is never anatomical.

# 5. Surface, colour, and markings

## 5.1 Surface material

The body uses:

```text
matte synthetic skin with soft mineral character
```

Desired material qualities:

- matte;
- low reflectivity;
- subtle micro-porous texture;
- slight soft-surface depth;
- tactile but not furry;
- organic but not fleshy;
- premium but not ceramic-glossy;
- dimensional but not plastic-toy-like.

Forbidden materials:

- exposed metal;
- chrome;
- armour composite;
- glossy plastic;
- rubber toy;
- wet biological skin;
- glass body;
- crystal;
- hard stone statue.

## 5.2 Base body colour

Canonical base:

```text
Mineral Body: #7EA1AC
```

This is a muted mineral blue-green/teal-grey and must remain visually distinct from the bright semantic runtime teal.

Production lighting may shift perceived values, but the body must remain subdued.

## 5.3 ChaseOS semantic colours

Use the ChaseOS semantic system:

| Token | Value | Canonical meaning |
|---|---:|---|
| Ink ground / visor | `#070B14` | private system environment and dark sensory surface |
| Signature edge start | `#4EB7FF` | provenance/graph signature |
| Graph violet | `#7C5CFF` | provenance, memory, relationships |
| Runtime teal | `#39E6D2` | agent is live or actively operating |
| Approval amber | `#F0B45A` | human intent, intervention, or approval required |
| Blocked red | `#FF4D6D` | blocked, failed, denied, or unsafe state |
| Bone | `#F4F1EA` | verified evidence, clarity, primary information |

These colours are semantic. They must not be used as arbitrary decoration.

## 5.4 Canonical markings

The selected base mascot includes subtle branching surface markings.

Canon interpretation:

- they are **provenance-growth marks**, not literal plant tattoos;
- they represent accumulated relationships, context, and learned structure;
- they remain low-contrast at rest;
- they may brighten slightly during active compilation or memory movement;
- they must not look like circuitry, tribal tattoos, veins, or armour seams.

Default locations:

- upper torso;
- sides of the head;
- lower legs/shins;
- optional restrained forearm continuation.

The default public mascot uses the selected canonical pattern.

## 5.5 User-instance markings

A user runtime instance may receive small custom surface patterns.

Permitted:

- pattern variation inside approved marking zones;
- subtle identity motif;
- prestige/progression markings;
- specialisation pattern;
- instance-specific pattern ID.

Not permitted:

- changing body anatomy;
- covering the entire body;
- sponsor logos;
- offensive or misleading symbols;
- using red, amber, or bright teal as permanent decoration;
- replacing the canonical face or visor.

# 6. Movement and physical behaviour

## 6.1 Default posture

- Upright.
- Alert.
- Balanced.
- Open enough to feel approachable.
- Stable enough to feel capable.
- No military stance.
- No slouching mascot posture.

## 6.2 Locomotion

Chaser Agent moves smoothly and almost weightlessly.

Normal movement:

- slight hover above the surface;
- feet remain visible;
- minimal vertical bounce;
- quiet acceleration;
- controlled directional changes;
- no superhero flight pose;
- no wheeled or mechanical movement.

## 6.3 Grounding behaviour

When work becomes consequential, Chaser Agent grounds itself.

Triggers include:

- awaiting approval;
- contradictory evidence;
- execution of an irreversible action;
- presenting a final packet;
- protecting a boundary;
- committing an approved workflow.

Visual response:

- descends;
- plants both feet;
- lowers centre of gravity;
- broadens stance subtly;
- reduces ambient motion;
- makes the approval or safety boundary visually explicit.

Core metaphor:

> **Exploration is fluid. Commitment is grounded.**

## 6.4 Interaction behaviour

The character uses:

- hands;
- visor;
- mouth;
- head tilt;
- body lean;
- stance;
- provenance ribbon;
- evidence fragments.

It should not require tools as part of the default silhouette.

Tools may appear only when a workflow genuinely requires one.

# 7. Provenance ribbon

## 7.1 Definition

The provenance ribbon is a temporary projected information trail.

It is not:

- a tail;
- clothing;
- a permanent aura;
- decorative orbit lines;
- a generic data stream;
- an always-on effect.

## 7.2 Activation

The ribbon appears when Chaser Agent is:

- tracking a goal;
- following sources;
- compiling evidence;
- moving memory;
- comparing possibilities;
- resolving a dependency;
- carrying context between workflow stages.

It disappears at rest.

## 7.3 Visual content

The ribbon may carry:

- source tokens;
- evidence fragments;
- memory shards;
- approval markers;
- unresolved nodes;
- provenance links;
- task checkpoints.

It should remain sparse and readable.

## 7.4 Motion

- smooth;
- directional;
- intentional;
- responsive to the character’s movement;
- no chaotic particle storms;
- no random swirls;
- no generic orbit.

# 8. Evidence and packet behaviour

## 8.1 Raw information

Raw sources and evidence appear as floating fragments.

They may be:

- small cards;
- abstract shards;
- bounded source glyphs;
- tiny provenance nodes;
- memory fragments.

They must not display private content in marketing artwork.

## 8.2 Compilation

During compilation:

- fragments gather between or above open hands;
- source paths remain visible;
- evidence and inference remain distinguishable;
- the visor shows organising or connecting signals;
- the ribbon carries provenance into the compiled object.

## 8.3 Resolved packet

A resolved packet:

- is physically presentable;
- may become bone-white;
- contains visible provenance;
- is not automatically executed;
- may still wait behind an amber approval gate.

## 8.4 Approval boundary

When approval is required:

- amber appears;
- the path pauses;
- the mascot grounds;
- hands remain open rather than committing;
- the operator remains the deciding authority.

# 9. Runtime-state canon

## 9.1 Dormant

- dim visor line or sparse low-energy points;
- no provenance ribbon;
- markings subdued;
- relaxed hover;
- neutral mouth;
- no implied unfinished approval.

## 9.2 Tracking

- runtime teal becomes active;
- directional dots or short connected paths appear in the visor;
- provenance ribbon appears;
- body leans subtly toward the active goal or source;
- hands may remain open for collection.

## 9.3 Compiling

- evidence fragments organise between the hands;
- teal and graph violet may coexist;
- visor shows structured connection patterns;
- ribbon carries source lineage;
- no amber unless operator action is required.

## 9.4 Uncertain

- incomplete amber node or question state;
- slow breathing pulse;
- movement pauses;
- visor shows open alternatives;
- mouth becomes neutral/concerned;
- the system asks the operator or presents options rather than guessing.

## 9.5 Contradiction

- two evidence paths remain separated or cross without resolving;
- visor shows competing indicators;
- violet may identify conflicting context;
- red is not used unless a path is unsafe or denied;
- Chaser Agent holds or presents alternatives separately.

## 9.6 Awaiting approval

- feet planted;
- stable stance;
- amber gate or operator marker;
- proposed packet visible;
- no execution motion beyond the gate;
- the character waits.

## 9.7 Approved

- approval state resolves;
- verified packet may become bone-white;
- active execution path may return to runtime teal;
- visor shows confirmation without celebratory excess;
- the operator decision remains attributable.

## 9.8 Correction

- incorrect path retracts visibly;
- fragments reorder;
- visor dims briefly;
- mouth and posture may show mild embarrassment/remorse;
- the corrected packet is presented transparently;
- no concealment of the prior error.

## 9.9 Blocked

- red appears on the denied object, terminated path, or explicit warning;
- the entire mascot does not turn red;
- Chaser Agent may raise one open hand;
- it positions itself between the unsafe action and the protected boundary;
- execution stops visibly.

## 9.10 Complete

- stable proof object;
- calm resolved visor;
- no unnecessary movement;
- provenance remains inspectable;
- final state feels settled, not celebratory or explosive.

# 10. Voice, sound, and communication

## 10.1 Voice identity

Chaser Agent should not sound fully human by default.

Direction:

- synthetic;
- companion-like;
- concise;
- calm;
- capable of small nonverbal tones;
- somewhere between expressive machine sounds and a restrained intelligent system voice.

The character may use:

- status tones;
- short synthetic vocalisations;
- concise phrases;
- visor emotes;
- text responses.

It must not imitate a child, cartoon animal, or overly emotional human.

## 10.2 Communication behaviour

When uncertain:

- ask;
- present competing possibilities;
- identify missing context;
- explain what would resolve uncertainty.

When wrong:

- acknowledge;
- correct;
- show the changed source trail;
- avoid defensive language;
- avoid pretending the previous state never existed.

When acting:

- indicate authority state;
- distinguish proposed from approved;
- preserve provenance.

# 11. Art-direction canon

## 11.1 Primary rendering style

Primary style:

```text
stylised 2.5D organic-digital character illustration
```

Characteristics:

- dimensional form;
- soft controlled shading;
- matte material;
- independent-comic / Western-animation influence;
- premium open-source mascot clarity;
- iconic line and silhouette discipline;
- no photorealism;
- no mecha detail;
- no glossy toy look.

The primary character may be built as a stylised 3D model to ensure consistency, but final renders must preserve the selected organic illustration feel.

## 11.2 Secondary styles

Allowed derivatives:

- clean 2D line art;
- flat vector icon;
- monochrome silhouette;
- simplified visor glyph;
- limited cel-shaded animation;
- documentation diagram;
- small emote/sticker style.

Every derivative must preserve the same anatomy.

## 11.3 Lighting

- deep ink environment for ChaseOS integration;
- soft directional key light;
- controlled rim light;
- minimal glow;
- state colour only where semantically justified;
- no cyberpunk neon bath;
- no hard metallic highlights.

## 11.4 ChaseOS framing

The mascot must remain recognisable without ChaseOS framing.

The ChaseOS parent identity may appear through:

- Sovereign Core logo;
- `Chaser Agent // ChaseOS` lockup;
- Provenance Graph background;
- state rings;
- interface frames;
- banners;
- runtime cards.

Do not fuse the ChaseOS logo into the mascot’s anatomy or stamp it permanently on the chest.

# 16. Acceptance criteria for the definitive production model

A production model may be called canonical only when:

- the same anatomy is maintained across front, three-quarter, side, and back views;
- the head matches the selected rounded-square form;
- the visor remains integrated and non-mechanical;
- hands have four rounded digits;
- feet have three integrated toes;
- body material reads matte and organic-digital;
- markings match the provenance-growth language;
- no armour/mecha cues appear;
- the silhouette works without ChaseOS framing;
- the profile crop remains recognisable at 64 px;
- dormant, uncertain, awaiting-approval, and blocked states are clearly distinguishable;
- semantic colour meanings are preserved;
- operator approval is never visually confused with agent activity;
- operator review explicitly approves the model.

A change requires a new major/minor canon version if it alters:

- anatomy;

- visor architecture;
- body colour family;
- markings system;
- runtime-state meaning;
- personalisation boundaries;
- relationship to the operator;
